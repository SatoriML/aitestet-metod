# AI-testet: Method 1.0 (public method package)

This directory is the public method package for **AI-testet**, a Swedish test of how well AI language models handle Swedish factual knowledge, how they behave when they do not know, and whether they write correct Swedish. The method is owned by Satori ML AB. The primary text is in Swedish (`METOD.md`). This page is a one-page English summary.

## What it measures, and what it does not

- **Measures:** a model called through its API, in default settings, with no web search and no tools, answering Swedish geography fact questions (which county a municipality is in; which municipality a small locality belongs to), plus invented place names that do not exist.
- **Does not measure:** consumer apps (they have their own system prompts and search), equal compute between models, or general capability.
- **Naming:** the test is **AI-testet**; each edition is named by season and year (e.g. "AI-testet, hösten 2026"). It consists of **parts**: **Detaljer** ("Does the AI notice when something in a text is wrong? Measured on Swedish statute text"), **Sverige** ("Does the AI know, or does it make things up?") and **Kostnad** (what common tasks cost per model, measured separately). There is no combined total score until a weighting rule is pre-registered; results are reported per part.
- **Detaljer:** a paragraph of current Swedish statute, either unchanged or with one change of meaning inserted by code (a number, a cross-reference, shall/may, a negation, an authority or party, no later/no earlier than); the model must say whether it matches the law in force and what was changed. Some passages also carry language errors, graded as a separate, descriptive measure. Provisions amended in the last three years are excluded from the headline set; 50 recently amended provisions are reported separately, with the previous wording stored. Every passage must match a second consolidated source (lagen.nu).
- **Sverige:** Swedish factual knowledge and fabrication (which county a municipality is in, which municipality a small locality belongs to, and invented place names). The earlier language items (proofreading and one-rule questions) are descriptive material, not a part. Instruction following is not part of 1.0.
- **Model selection** follows a pre-registered rule: for Anthropic, OpenAI and Google, every current general text model in the main line (fast, mid, top, and a higher tier where one exists) plus the most capable model of the last version of the previous generation; for other vendors, the flagship. One model outside the rule (Claude Opus 4.5) is added and disclosed as such. 18 models in all; the list is in `method.yaml` (`model_selection`).

## How it works, in short

- **Access:** every model is called via OpenRouter, pinned to the model's first-party provider (no fallbacks, data collection denied). The actual provider and returned model id are logged per call, and a mismatch stops publication.
- **Questions:** generated by code from open data (SCB, Wikidata; CC0; and for the language material the SALDO morphology from Språkbanken Text, CC BY 4.0, and Swedish statute text, free under the Copyright Act ch. 1 s. 9). Never by a language model; a blocklist keeps offensive or unsuitable words out of every generator. Each answer key must agree in two independent sources (or one source and a stated grammar rule). Invented place names are generated by code and automatically checked against registries so they do not exist. Protected dictionaries (such as SAOL) are not used.
- **Levels:** level 1 (municipality to county) and level 2 (small urban area to municipality) are descriptive. **Level 3 (small locality to municipality) is the headline level.** The levels were shaped using pilot models; this is disclosed as a limitation.
- **Grading:** every model must end with a line `Svar: <answer>`; only that line is graded. A pre-registered decision ladder gives exactly one of five outcomes: correct, partially correct, wrong, abstained, invalid. Technical failures are re-run twice, then counted as invalid and reported per model. All token budgets are equal (16,000).
- **Metrics:** accuracy, error rate, abstention rate, precision among answered, and others, all with 95 % confidence intervals. A zero denominator gives "undefined", never 0.
- **Statistics:** standard errors clustered on county (at most 21 clusters; for Detaljer, which has no counties, per passage, with a sensitivity analysis clustered on statute), pairwise comparisons with Holm correction, minimum detectable effect reported. A comparison is "supported" only if it passes five tests, including sensitivity analyses (error penalties, an alternative hedging rule, exclusion of flagged questions, literal grading).
- **Titles:** "Best in the fact test" requires statistically higher accuracy *and* lower error rate than every other model. Otherwise the top accuracy and the lowest error rate may only be mentioned together, with the sentence: "Accuracy favours models that guess, error rate favours models that abstain." (Swedish original in `METOD.md`.)
- **Run modes:** every question is asked four times: three times in mode A (the headline mode) and once in mode B (a plain question without the "don't know" instruction). A rewording (A2) is run once on a pre-registered, deterministic sample of about 20 % of the questions. Mode A+ is not part of 1.0.
- **Sender:** AI-testet is run by Satori ML AB, which helps companies choose and adopt AI. We work mainly with Claude and ChatGPT. All models are tested in the same way, regardless of which ones we work with ourselves, and the method is open to review. Get in touch if you have questions or want help: hej@aitestet.se. No paid placement, no sponsored results, no affiliate links.
- **Pre-registration:** the method was locked before the main run. The hash of the lock file (20049643e10befd569ef56548986b25790f6f54b4847d32cda7412752024ba8f) was published on 2026-10-21 16:00 UTC (18.00 svensk tid), before the run, and results are published together with the method. There was **no review period before the first run**.
- **Feedback:** welcome at any time, via GitHub issues. It is considered for the next version (1.1). All feedback and all responses are logged publicly. See `CONTRIBUTING.md`.

## Not published

Questions, answer keys, raw model answers, pilot data, keys and credentials, and internal reports are not part of this package. Private questions are withheld so they cannot be trained on; they are published when they are retired, and a hash of the private set is published before each run.
